# 1.0.0 release validation

The first public release promotes the 0.1.0 candidate and adds in-place Windows upgrades. All workspace
packages, the frontend package and Tauri metadata use 1.0.0. Earlier privacy, provenance and owner visual
acceptance are recorded in [the candidate validation](0.1.0-validation.md).

## Local verification

- Rust formatting, Clippy with warnings denied, workspace tests, frontend type/lint/format checks and the
  production NSIS build passed. Game-data tests and the real-install report test ran against Longshot
  v3.0.0-rc.5. The optional golden comparison and optional standalone save test had no private inputs and
  skipped; their test-runner success lines do not represent reference/save comparisons.
- The installer template is adapted from the exact locked Tauri CLI version. Its source revision, licence,
  changes and future upgrade checks are in [the installer guide](../../app/src-tauri/windows/README.md).
- With a separate test-only installer identity, a 0.1.0 installation was upgraded to 1.0.0 in passive mode.
  Its old uninstaller was replaced with a sentinel executable that would record invocation and fail: it
  was never invoked. Installation and local-data sentinels survived unchanged. The installed executable
  matched the new binary, one Installed apps entry showed 1.0.0, and a conflicting `/D` directory was ignored.
- Silent same-version repair passed. A simulated newer installed version rejected a downgrade without
  changing the installed version, executable or sentinels. The separate test installation was uninstalled.
- A fresh silent 1.0.0 installation launched an Ocarina Journal window and remained running with isolated
  data directories. Its product version was 1.0.0; the owned test process was stopped and the test install removed.
- The extracted local installer had eight expected application, licence and installer-component files.
  A scan of 269 publishable files and the extracted installer found no matching owner identifiers or paths.
- The normal interactive flow uses the same initialization and skips the uninstall-choice and directory
  pages for an existing NSIS installation. Native UI automation was unavailable; this is verified from the
  rendered script and passive integration test, not represented as a visual installer test.

## Publication gate

Publish only after the final release source passes hosted CI and the tagged release workflow builds its
draft. Download and inspect that hosted installer, include corresponding tagged source and checksums,
and verify the public release metadata after publishing. A local build does not substitute for inspecting
the hosted artifact. The Windows installer is unsigned.
