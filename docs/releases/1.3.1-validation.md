# 1.3.1 release validation

This patch fixes repeat QR scans in paired browsers and shares app-owned notification acknowledgements and
journal progress between the desktop and paired screens. The game and saves remain read-only.

## Local verification

- Windows workspace formatting, Clippy with warnings denied and workspace tests passed. No real game, golden
  reference or private save inputs were supplied for this patch, so those optional checks skipped.
- Frontend types, ESLint, Prettier, production build and seven browser regressions passed. The new two-store
  regression checks tile acknowledgements in both directions, stale migration/snapshots and retry after failure.
- Rust merge/validation tests check preservation of unrelated entries, numeric best values, explored-room union,
  persisted-state round-trip and rejection of invalid values or desktop-setting keys. Socket tests enforce pairing
  and origin restrictions for progress sync. There are 20 second-screen integration tests and six crate unit tests.
- QR regressions check that an existing session reloads without a pairing attempt, while new/revoked sessions
  use the QR code and ask for the separate PIN. Network failures and timeouts have a fallback. The pairing script
  remains available when its request includes a cookie omitted from the initial navigation.
- The release description is generated from CHANGELOG.md and includes both 1.3.1 and 1.3.0 in full.

## Publication gates and limits

The unchanged hosted workflow must pass Windows and Linux builds/startup checks for the immutable release tag.
Before publication inspect downloaded packages and source, verify digests and attach source plus SHA256SUMS.txt.
Packages are unsigned. Local Windows checks do not establish clean Linux package installation, physical-phone
QR scanning, home-screen installation or live Linux gameplay. No new artwork or dependencies were added.
