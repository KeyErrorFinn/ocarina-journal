# 1.1.1 validation

**Date:** 2026-11-23. A patch release: the game maps were blank in the installed 1.0.0 and 1.1.0 because the app's
Content Security Policy had no `blob:` source for images. Details are in [CHANGELOG.md](../../CHANGELOG.md).

## What was checked

- **Before merging**, on the hosted runners: Rust (fmt, clippy, tests) on Windows, the Linux build with its smoke
  test, the app's types, lint, format and build, the repository rules (now including `scripts/check-csp.py`), and the
  new Windows job, which builds the release app and loads its page under the real policy
  (`scripts/smoke-windows.mjs`). The Windows job was run against the old policy locally and failed with
  "a blob: picture is blocked", so it does catch this bug.
- **The release workflow** built the Windows installer and the Linux packages from the `v1.1.1` tag and ran the
  policy checks before the release was published.
- **The published installer** was extracted: the shipped `ocarina-journal.exe` carries
  `img-src 'self' data: blob:` and version 1.1.1; the installer holds only the app, its licence notice and installer
  files. A scan of the executable and the source archive for the owner's name, email and Windows user paths found
  nothing personal (one hit is the German word "Finnland" in the 1.1.0 validation notes).
- **On a real install**, the fixed build showed the Hyrule world map and area maps from the player's own game files.

## Not checked

- The Linux packages were built by the release workflow and the Linux binary was started in CI, but the 1.1.1 `.deb`,
  `.rpm` and AppImage were not installed on clean machines again (1.1.0's were; see
  [its validation](1.1.0-validation.md)). Their contents differ from 1.1.0's only by the frontend fix.
- The policy check covers WebView2 (Windows). WebKitGTK on Linux is checked by the static policy check only.
