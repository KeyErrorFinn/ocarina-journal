# 1.1.0 release validation

Adds the Linux build (x86_64: `.deb`, `.rpm`, AppImage). All workspace packages, the frontend package and the Tauri
metadata use 1.1.0. What the Linux build assumes about Longshot, and where each assumption comes from, is in
[`docs/research/LINUX.md`](../research/LINUX.md). The Windows release process and checks are unchanged; see
[the 1.0.0 validation](1.0.0-validation.md).

## Verified locally (Windows development machine)

- Rust formatting, Clippy with warnings denied, the whole workspace's tests, the frontend type, lint and format
  checks and the production frontend build passed. The game-data and save-file tests also ran against Longshot
  v3.0.0-rc.5.
- The Windows app was rebuilt and started after its host paths moved into `app/src-tauri/src/platform.rs`: it
  found the six save slots and showed the Home screen with no console errors.
- The Linux code paths of the library crates (`oj-bridge`'s Unix-socket client and its Unix-socket test,
  `oj-savefile`'s Linux data folder, `oj-journal`, `oj-protocol`, `oj-testkit`) were type-checked and linted for
  `x86_64-unknown-linux-gnu` with warnings denied. `app/src-tauri/src/platform.rs` was linted on its own for both
  targets. `oj-gamedata` could not be cross-checked here (its zstd dependency needs a Linux C compiler).
- `scripts/check-linux-glib.py` found no use of the unsound glib iterator (RUSTSEC-2024-0429) in the 304 locked
  packages. The CI and release workflow files parse as YAML.

## Verified by hosted CI

The hosted [CI run for the release pull request](https://github.com/KeyErrorFinn/ocarina-journal/actions/runs/45062781205)
passed all four jobs. The **Linux** job, on Ubuntu 22.04, ran Clippy with warnings denied, the workspace tests
(including the bridge client against a real Unix socket), the glib tripwire, a release build of the app, and a
start-up smoke test in a virtual X11 display with no game and with a synthetic report: the process stayed alive,
an "Ocarina Journal" window was present, and the private app-data folder was created.

## Not verified

- **The packages.** That the `.deb`, `.rpm` and AppImage install and run is checked only on the hosted release
  artifacts (see the publication gate below), not by this CI run, which builds the binary without packaging.
- **No run against a live Linux Longshot game.** The bridge client is tested against a fixture on a real Unix
  socket, not against Longshot.
- Wayland, and distributions other than Ubuntu, are untested.
- The persistent "turn the bridge on" switch is not offered on Linux (see `docs/research/LINUX.md`).

## Publication gate

Publish only after the final source passes hosted CI on both platforms, including the new **Linux** job, and the
tagged release workflow has built a draft containing the Windows installer and the three Linux packages. Download
and inspect each hosted artifact (install the `.deb` and `.rpm` in a clean container or machine, run the AppImage),
check that none contains owner data or game files, add checksums for all of them, and verify the public release
metadata after publishing. Add the Linux CI check to the required checks on `master` once it has passed there. The
Windows installer and the Linux packages are unsigned. If an inspection fails, fix it before publishing, or publish
Windows only and say so in the release notes.
